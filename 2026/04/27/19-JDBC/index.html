4 DCL(事务)

事务是逻辑上的一组操作，组成这组操作的单元要么同时成功，要么同时失败。

4.2 代码级别使用事务

事务的控制是在业务逻辑层，因为事务不是和数据库相关，是和真正的业务相关

事务的控制要求是同一个连接

事务的回滚要注意捕获到对应的异常

4.3 事务的特性和隔离级别[面试题]

4.3.1 事务的特性

  • 原子性:指事务是一个不可分割的工作单位，事务中的操作要么同时成功，要么同时失败
  • 一致性:事务前后的数据的完整性要保持一致
  • 持久性:事务一旦提交，对数据库的数据改动是永久性的
  • 隔离性:指多个用户并发操作数据库时，一个用户的事务不能被其他用户的事务所干扰。简单来说，事务之间互不干扰。

4.3.2 没有隔离性会引发的问题

可能出现的问题 含义
脏读 一个事务读取到了另一个事务尚未提交的数据
不可重复读 一个事务中两次读取到的数据的内容不一致。这是由update引起的
幻读 一个事务中两次读取到的数据的数量不一致。这是由insert 或delete引起的

4.3.3 事务的隔离级别

级别 名字 隔离级别 脏读 不可重复读 幻读 数据库默认级别
1 读未提交 read uncommitted 是 是 是
2 读已提交 read committed 否 是 是 oracle
3 可重复读 repeatable read 否 否 是 mysql
4 串行化 serializable 否 否 否

隔离级别越高，安全性越高，性能越差

什么是装饰者设计模式?

是23种常用的面向对象软件设计模式之一。动态地将责任附加到对象上，若要扩展功能，装饰者提供了比继承更加有弹性的替代方案。

作用:改写已存在的类的某些方法或者进行增强。

使用的条件:

  • 增强类和被增强类要实现同一个接口或者同一个父类
